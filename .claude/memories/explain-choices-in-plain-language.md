# Explain choices in plain language

When a choice depends on a tool or domain the user hasn't worked with, don't ask a technical multiple-choice question. Build each option, render it, show them side by side in plain language with what each means for what the user will see, give a recommendation, and let the user pick by looking.

**Why:** A question framed in a tool's own terms can't be answered by someone who only knows what the tool is for, so it stalls the work.

**How to apply:** Make the comparison an artifact page with real renders. Give defaults for the smaller choices so the user only decides what visibly matters. See [[readme-diagrams-are-mermaid]].
